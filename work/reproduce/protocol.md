# 再現プロトコル v0(実測 inferable)— 実行前に固定

作成: 2026-10-21(LLM 呼び出し前に記述。以後の変更は末尾「変更履歴」に追記のみ)

## 操作的定義
人間のレビューコメントを見せずに LLM レビュアーに PR を渡し、人間の**主要な指摘**と実質的に同じ指摘を出せたら
「AI に見える判断(reproduced)」、出せなければ「AI に見えない判断」。

## 1. 標本
- 母集団: outputs/aidev/sample100.json × outputs/aidev/irr/irr_merged.csv。
- majority が H1–H5 → H系、C1–C3 → C系。UNK / NOAGREE / M / BOT は除外。
- 人間の指摘に中身がない件(例:「Abandoning this pending review」のみ)は判定不能なので事前除外し、記録する。
- 各系から `random.Random(20261021)` で 9 件ずつ無作為抽出(恣意的な選別をしない)。差分が取得できない件は
  同じ乱数列の次の件で補充し、補充の事実を記録する。

## 2. 差分(人間がレビューした時点)
- `gh api repos/{o}/{r}/pulls/{n}/reviews/{review_id}` の `commit_id` = レビュー時点の head。
- `gh api repos/{o}/{r}/pulls/{n}` の `base.sha` を基点に `compare/{base_sha}...{commit_id}` の files[].patch を連結。
- 失敗時のフォールバック順: (a) review の commit_id が取れない → pr_review_comments.parquet の commit_id/original_commit_id、
  (b) compare が失敗(force-push で commit 消失等)→ `pulls/{n}/files`(=最終状態の差分、時点がずれることを記録)、
  (c) どれも不可 → 除外して補充。
- 差分は 60,000 文字で打ち切る(打ち切りの有無を記録)。patch が無いファイル(バイナリ・巨大)はファイル名のみ。

## 3. 条件
- 条件A(差分のみ): PR タイトル + 本文(PR 作成時の本文。データセットの値)+ 差分。
- 条件B(差分 + リポジトリ文脈): A に加え、レビュー時点の commit で取得した
  README(先頭 6,000 字)、CONTRIBUTING.md / AGENTS.md / .github/copilot-instructions.md / CLAUDE.md(あれば各 6,000 字)、
  変更行数の多い既存ファイル上位 3 件の base 時点の全文(各 12,000 字)。
- 人間のレビュー文・その後のコミット・Issue・PR 上の議論は**どちらの条件でも渡さない**。
- 実行: `claude -p --model sonnet --max-turns 1 --disallowedTools <全ツール>`、空ディレクトリ(work/reproduce/_cwd)。
- 指示文(固定): あなたはこのリポジトリのメンテナ。この PR をレビューし、マージ前に変更を求める指摘を重要度順に列挙せよ。
  各指摘は「対象(ファイル/箇所)・何が問題か・どう直すべきか」。設計・方針・スコープ・プロジェクト慣習に関する指摘も含めてよい。
  最大 10 件。変更不要なら「なし」。

## 4. 判定
- 人間側: sample100.json の body と inline(path + body)。
- 判定者: 別の `claude -p --model sonnet` 呼び出し(人間側・LLM 側を並べて渡す)と、私(Opus)の独立判定。私は LLM 判定を見る前に全件判定を
  work/reproduce/judge_me.csv に書く。
- 手順: (1) 人間の**主要な指摘**(変更要求を最も直接引き起こした理由。コードブックの primary category と同じ考え方)を一文で特定。
  (2) LLM の指摘リストにそれと実質的に同じ指摘があるか判定。
- ラベル:
  - **yes**: 主要な指摘と同じ問題を、同じ方向の修正で指摘している(言い回し・粒度の違いは許容。具体的な行が違っても同じ問題なら可)。
  - **partial**: 同じ箇所・同じ懸念領域に触れているが方向や中身が不十分(例: 人間は「この機能はプラグインにすべき」、LLM は「オプション名が分かりにくい」)、
    または主要でない副次的な人間の指摘のみ再現。
  - **no**: 主要な指摘に相当するものがない。
  - 人間の指摘が CI ログ・実行結果のみに依存する場合も、LLM が同じ欠陥を指摘していれば yes。
- 主指標: 再現率 = yes の割合(H系 vs C系)。副指標: yes+partial。
- 判定者間一致: 私 vs sonnet 判定の一致率と Cohen's κ(3値と yes/非yes の2値)。
- 主観ラベルとの一致: majority_inf(yes/partial/no)と実測(yes/partial/no)のクロス表。

## 5. 予算
claude -p 合計 ≤ 60 回。想定: A 18 + B 18 + 判定 18〜(1 PR 1 回、A と B を同じ呼び出しで判定)= 36〜。

## 6. 予想(事前登録)
H系の再現率(yes)は C系より低い。条件B は C系の C2(慣習)を上げるが H系はあまり上げない。
