The `BlobPropertiesInternal` struct had an incorrect serde field rename that caused the `etag` property to always be `None` when deserializing Azure Blob Storage REST API responses.

## Problem

The generated code was using `#[serde(rename = "ETag", ...)]` for the etag field, but according to the [Azure Blob Storage REST API documentation](https://learn.microsoft.com/en-us/rest/api/storageservices/list-blobs), the actual field name in API responses is `"Etag"` (lowercase 'e').

This mismatch meant that when calling `BlobContainerClient.list_blobs()`, the returned blob objects would always have `etag` set to `None`, even though the API response contained valid ETag values.

## Solution

Changed the serde rename from `"ETag"` to `"Etag"` in the `BlobPropertiesInternal` struct:

```rust
// Before (incorrect)
#[serde(rename = "ETag", skip_serializing_if = "Option::is_none")]
pub etag: Option<String>,

// After (correct)  
#[serde(rename = "Etag", skip_serializing_if = "Option::is_none")]
pub etag: Option<String>,
```

## Testing

Added comprehensive tests to verify the fix:
- Confirms that JSON with `"Etag"` field correctly populates the etag property
- Confirms that JSON with `"ETag"` field no longer populates etag (expected behavior)
- Tests the real-world scenario of parsing list_blobs API responses
- Verifies all existing tests still pass

## Note

This is a manual fix applied to generated code. The change includes documentation explaining that this is a temporary fix until the upstream TypeSpec/API specifications are corrected. Future regeneration of this code will need to preserve this fix or address it at the specification level.

Fixes #2830.
