## Summary

The SDK now automatically suppresses the CS8002 warning (referenced assembly doesn't have a strong name) for C# projects targeting .NET Core (.NETCoreApp) and .NET Standard TFMs. This warning is irrelevant on modern .NET runtimes where strong-name validation has been removed, and was creating noise for users.

## Changes

Modified `Microsoft.NET.Sdk.CSharp.targets` to append CS8002 to the `NoWarn` property when the project targets .NETCoreApp or .NETStandard, using the existing `_IsNETCoreOrNETStandard` property for detection.

The suppression is applied automatically by the SDK and requires no action from users. Projects targeting .NET Framework (.NETFramework) are unaffected and will continue to receive CS8002 warnings if applicable.

## Examples

**Before this change:**
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <!-- Users had to manually add CS8002 to suppress the warning -->
    <NoWarn>$(NoWarn);CS8002</NoWarn>
  </PropertyGroup>
</Project>
```

**After this change:**
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <!-- CS8002 is now automatically suppressed for .NET Core/Standard -->
  </PropertyGroup>
</Project>
```

## Testing

Added comprehensive tests in `GivenThatWeWantToSuppressCS8002Warning.cs` that verify:
- CS8002 is suppressed for net6.0, net7.0, net8.0, netstandard2.0, and netstandard2.1
- CS8002 is NOT suppressed for net472 and net48 (.NET Framework)
- CS8002 suppression works correctly alongside existing NoWarn values

All tests pass successfully.
