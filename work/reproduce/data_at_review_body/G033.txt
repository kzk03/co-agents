Closes #1243

This PR introduces a new experimental `virtual:fullstack/no-split-css` module that provides a simplified API for collecting all CSS in the server module graph during development. This addresses use cases where code-splitting by route is not important and a simpler approach is desired.

## What's New

The new `virtual:fullstack/no-split-css` module can be imported from server environments to automatically collect all CSS files. This feature must be explicitly enabled via the `experimental.noSplitCss` flag:

```js
// vite.config.ts
import fullstack from "@hiogawa/vite-plugin-fullstack";

export default {
  plugins: [
    fullstack({
      experimental: {
        noSplitCss: true, // Enable the feature
      },
    }),
  ],
};
```

```js
// entry.server.tsx
import noSplitCss from "virtual:fullstack/no-split-css";

export function renderHtml() {
  return `
    <html>
      <head>
        ${noSplitCss.map(css => 
          `<link rel="stylesheet" href="${css.href}" ${css['data-vite-dev-id'] ? `data-vite-dev-id="${css['data-vite-dev-id']}"` : ''} />`
        ).join('\n')}
      </head>
      <body>...</body>
    </html>
  `;
}
```

## Key Features

- **Experimental**: Must be enabled via `experimental.noSplitCss` option (default: false)
- **Dev-only**: Works only in development mode (returns empty array in build mode)
- **Server-side**: Returns empty array in client environment
- **Comprehensive**: Collects all CSS files from the entire server module graph
- **HMR-compatible**: Includes `data-vite-dev-id` attributes for proper hot module replacement
- **Type-safe**: Full TypeScript support with proper type declarations

## Comparison with Existing API

This complements the existing `?assets` query import approach:

| Feature | `?assets` Query | `virtual:fullstack/no-split-css` |
|---------|-----------------|----------------------------------|
| Code-splitting per route | ✅ Yes | ❌ No |
| Simplicity | Medium | ✅ High |
| Dev + Build | ✅ Both | 🔶 Dev only |
| Granular control | ✅ High | ❌ Low |
| Requires flag | ❌ No | ✅ Yes (experimental) |

Use `virtual:fullstack/no-split-css` when:
- You don't need per-route code-splitting
- You want the simplest possible setup
- You're primarily focused on development experience

Use `?assets` query when:
- You need granular control over asset loading
- Code-splitting by route is important
- You need production build support

## Implementation Details

The module:
- Recursively traverses the server module graph
- Collects all CSS imports using Vite's `isCSSRequest()` 
- Skips special CSS queries (`?url`, `?inline`, `?raw`)
- Avoids circular dependencies by skipping virtual asset modules
- Returns normalized URLs compatible with Vite's import analysis
- Only activates when `experimental.noSplitCss` is enabled
