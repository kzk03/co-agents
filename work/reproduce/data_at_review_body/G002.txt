## Summary

Adds telemetry collection for Microsoft-authored tasks to help inform decisions about making tasks `sealed` and other API changes. This addresses the requirements outlined in #10855.

## Changes

### Telemetry Collection
- **New telemetry event**: `build/tasks/microsoft` tracks characteristics of Microsoft-authored tasks
- **Metrics collected**:
  - `MicrosoftTasksLoadedCount`: Total number of Microsoft tasks instantiated
  - `MicrosoftTasksSealedCount`: Number of sealed tasks
  - `MicrosoftTasksInheritingFromTaskCount`: Number of tasks inheriting from `Microsoft.Build.Utilities.Task`

### Implementation Details

**Modified `ProjectTelemetry.cs`**:
- Added `AddMicrosoftTaskLoaded(Type)` method that inspects task types to collect:
  - Whether the task is sealed (via `Type.IsSealed`)
  - Whether it inherits from `Microsoft.Build.Utilities.Task` (by walking the inheritance chain)
- Telemetry is aggregated per project and logged when the project build completes

**Modified `AssemblyTaskFactory.cs`**:
- Added `IsMicrosoftAuthoredTask()` helper that identifies Microsoft tasks by checking:
  - Assembly name starts with "Microsoft."
  - Assembly is from built-in MSBuild logic location
  - Assembly is a Microsoft package from NuGet cache
- Collects telemetry after task instantiation in `CreateTaskInstance()`

**New test file `ProjectTelemetry_Tests.cs`**:
- 6 comprehensive unit tests covering all code paths
- Integration test that verifies telemetry collection during actual builds

## Example Output

For a build using Microsoft tasks like `Message` and `Csc`:
```
TelemetryEvent: build/tasks/microsoft
Properties:
  - MicrosoftTasksLoadedCount: 2
  - MicrosoftTasksSealedCount: 0
  - MicrosoftTasksInheritingFromTaskCount: 2
```

## Performance Considerations

- Minimal overhead: only tracks Microsoft-authored tasks
- Uses simple integer counters, no complex data structures
- No additional reflection beyond what MSBuild already does
- Telemetry logged once per project, not per task execution

## Extensibility

The implementation is designed for future extensions:
- Additional task characteristics can be easily added (e.g., IMultiThreadedTask support once those APIs are available)
- External SDKs could potentially register their own tasks for tracking
- Can be extended to log per-task details if needed

## SDK Integration

Follows the existing telemetry pattern where the SDK's `MSBuildLogger` aggregates integer properties across builds and sends them to the telemetry backend. See: https://github.com/dotnet/sdk/blob/main/src/Cli/dotnet/Commands/MSBuild/MSBuildLogger.cs
