### 設計の点検
1. **H と inferable はほぼ同じ変数**:C 系に inferable=no は0件、H 系に inferable=yes は0件
2. **GitHub の H は「コードからは分からない判断」とは言いにくい**:H 18件のうち inferable=no は3件。14件は H2 で、事前に文書化できる設計意図や規約が多い。G045 は手続き上のノイズ
3. **測定条件が違う**:Gerrit の分類ダンプは投票の強さと結末を見せている。GitHub は隠している
4. **層の切り方が違う**(Gerrit は投票×時期、GitHub は結末)。repo・レビュアーごとの上限は重みで補正していない
5. **感度分析**
   - 層内ブートストラップの95%区間:Gerrit 0.283–0.510、GitHub 0.093–0.268
   - UNK/NOAGREE をすべて H かすべて C とした上下限:Gerrit 0.360–0.453、GitHub 0.147–0.309
   - コーダー別の推定:GitHub は Opus 0.274 / Sonnet 0.219 / Haiku 0.177、Gerrit は 0.411–0.432
   - → Gerrit > GitHub の大小関係は崩れない。ただし GitHub の水準はコーダーによって約1.5倍動く
6. コーダーはすべて同じ社のモデルで、人間がいない
7. Copilot の CR はゲートではなくプロンプトに近い(サンプルの83%が Copilot)
8. baseline の候補データ:CR 4,321件中3,041件が home-assistant/core

## 批判の本体

### 1. 構成概念
- H は3種類を混ぜている
  - (a) **情報の欠如**:渡せば解けるので、モデルとアクセスが強くなれば縮む
  - (b) **書かれていない設計意図・規約**:事前に文書化でき、AGENTS.md の守備範囲
  - (c) **権限・価値・責任の判断**:情報をすべて渡しても、決める主体が要る
- HUMANS.md 固有の論拠になるのは (c) と、(a) のうち人間しか持ちえない情報
- 「コードから分からない」は、LLM がテキストの印象で判定しているだけで、操作的定義になっていない
- Hirao は外部要因は自動化できると結論している。Wang の Duplicate 40.78% は H1 に当たる
- 人間による校正が必須(人間2名で50〜100件)

### 2. 交絡
- 作者、レビュー文化、エコシステム、時期、タスク、測定条件、層設計が交絡している
- 対処:①Gerrit を盲検ダンプで再コード、②同じ repo 内で人間 PR とエージェント PR を比較、③Gerrit と GitHub の比較は「別文化での再現」と位置づける
- repo 上限が未補正。UNK をランダムな欠測とみなしている。-2 の14/15には区間を付ける

### 3. スケール
- 殺されるのは (a) と (b)。レビューという観測窓そのものが縮んでいる(Duma:AI PR の61.38%にレビュー記録がない)
- 殺されないのは (c)(能力ではなく正統性の問題)
- → 「情報をすべて渡しても残る差」として定義し、モデルの世代ごとに測り直せる手順にする

### 4. 査読者が突く点トップ5
1. 構成概念と LLM だけのコーディング → v1(情報/規約/権限・責任)、人間2名、inferable は実測に置き換える
2. 交絡 → 盲検での再コード、同じ repo 内の比較、repo を変量効果にする
3. 選択バイアス(理由を書かずに止めたもの) → 分析単位を介入イベントに広げる、「言語化された場合に限る」と結論を限定する
4. 新規性 → 再現できない残差を中心に据える
5. 規範的結論への飛躍 → HUMANS.md を責任分担を明示する文書と定義し、既存の AGENTS.md/CONTRIBUTING と照合する

### 5. RQ の立て直し案
- **A 残差(推奨)**:全情報を与えた LLM でも再現できない理由は何か。それは情報・規約・権限のどれか
- **B 判断の所在**:判断はライフサイクルのどこに現れるか。人間 PR と比べて上流に移っているか
- **C 文書化可能性**:事前に書けた理由はどれだけあり、実際に書かれていたか
- 推奨:A を主 RQ、C を A の解釈に使う、B は副 RQ

## 他の担当への注文
- **baseline**:repo の偏りを補正する、同じ repo で比べる、ダンプの形式を揃える、repo ごとの CR 使用率を出す
- **delegation**:人間 PR 側の Issue と比べる。(i) 依頼文にあってレビューでも繰り返された、(ii) 依頼文にあってレビューでは出なかった、(iii) 依頼文になくレビューで初めて出た、を区別する。エージェント別に分ける。上流で観測できる分は下限と明記する
- **reproduce**:H 系を全件にする、条件C(Issue や先行議論も渡す)を追加する、判定は上位3件までに限る、群ラベルを伏せて判定する、複数のモデル世代で回す
