# 関連研究の精査(critic)

取得日: 2026-10-21。arXiv は abs と html 版、古典論文は PDF 本文から確認(pdftotext)。数値は原文から転記。確認できなかったものは「未確認」。
「差分」= 本研究(人間がレビューで止めた理由 → HUMANS.md に書くべき事項)との違い。

## A. エージェント PR の拒否・レビュー(直接の競合)

### Peralta et al. "Why Are Agentic Pull Requests Merged or Rejected? An Empirical Study" arXiv 2605.22534(MSR 2026 採録)
- 著者: S. R. O. Peralta, F. Hoshi, H. Washizaki, N. Ubayashi, I. Kondo, Y. Higo, H. Mukai, N. Yoshida, K. Kusama, H. Tanaka, Y. Fan
- データ: AIDev の closed Agentic PR、star≥500 の repo。11,048 → 人間レビューのある 9,799 件。エージェント構成 Codex 40.7% / Devin 34.5% / Copilot 14.6% / Cursor 8.0% / Claude Code 2.2%。
- 方法: 717 件を手作業で分析(rejected 353 / merged 364、エージェントと repo でバランス)。1 PR を 2 人が独立にコード化、4 人。κ≈0.90(rejected)、κ=1.0(merged)。
- 結果(rejected, N=353): Agentic failure 126(35.7%)/ Non-agentic failure 110(31.2%:重複・置き換え・放置・テスト PR・提出先違い)/ **Unknown 117(33.1%)**。
  merged(N=364): フィードバックループなし 288(79.1%)/ ループあり 28(7.7%)/ 人間の介入 28(7.7%)/ Unknown 20(5.5%)。
- **33.1% の定義**: 「コメント・CI 結果・クローズの文脈のいずれにも信頼できる判断シグナルが観測できない」もの。主に「コメントなしでクローズ」など repo 側の沈黙による。著者はエージェントの失敗を意味しないと注記。
- 差分: 単位が PR の結末、理由は「エージェントの失敗か否か」の軸。人間の判断の中身(文脈・方針・責任)は分類していない。Unknown 33.1% は本研究が「理由テキストのある CR」に条件づけていることの裏返し。

### Duma et al. "These Aren't the Reviews You're Looking For: How Humans Review AI-Generated Pull Requests" arXiv 2605.02273(EASE 2026 採録)
- 著者: K. Duma, P. Wróblewski, J. Bobińska, J. Winiarska, P. Przymus
- データ: AIDev、star≥100。R_pop の AI PR 33,596 件、AI と人間の PR が共存する repo(R_∩)の AI PR 9,616 件。
- 方法: ルールベースで人間コメントを Agentic(エージェント操縦: 命令形＋エージェント名)/ Automation / Human Review に分類。
- 結果: R_pop で AI PR の 61.38% はレビュー記録なし、58.77% はエージェントのみがレビュー、コメントの 28.42% が人間。人間コメント中 64.53% が直接レビュー、28.37% が操縦、7.10% が自動化。
  R_∩: レビューあり AI 71.08% vs 人間 65.48%、人間のみのレビュー AI 8.08% vs 人間 25.21%、人間コメント中の操縦 AI 25.92% vs 人間 1.63%、直接レビュー AI 65.53% vs 人間 93.56%。
- 限界(著者): コメントがないことはレビューされていないことを意味しない。PR サイズ・repo の運用は統制していない。
- 差分: 量(誰がレビューしたか)の研究で、理由の中身は扱わない。**同じ repo で人間 PR と比べる設計(R_∩)は baseline 担当がそのまま借りるべき**。本研究の「@copilot 宛て 40%」は彼らの「操縦 25.92%」と同じ現象。

### Abujadallah, Arabat, Sayagh "Understanding the Rejection of Fixes Generated by Agentic Pull Requests — Insights from the AIDev Dataset" arXiv 2606.13468(MSR 2026)
- データ: AIDev-pop(33,596 PR / 2,807 project)の fix PR 3,225 件(Copilot, Devin, Cursor, Claude)。拒否 1,497 件(46.41%)から 306 件(95% 信頼・誤差 5%)。
- 結果: 14 理由・4 カテゴリ。Relevance 23.5%(放置 17.3%、置き換え 5.9%、低優先 1.0% …)、Implementation 11.6%(誤修正 5.6%、誤ったアプローチ 2.6% …)、Technical 7.2%(CI 失敗 6.9%)、Provider 8.5%(エージェント失敗 7.5%、レート制限 1.0%)。**明示的な理由がなくラベルなし 151 件(49.3%)**。κ=0.605。
- 提言: エージェントに「アプローチのヒント」「制約・制限」「CI での検証方法」を与える。
- 差分: fix PR のみ、PR 単位。理由の半分が観測不能。提言(依頼文に制約を書け)は delegation 仮説と同じ方向だが検証はしていない。

### Alam, Mondal, Roy "Why Are AI Agent Involved Pull Requests (Fix-Related) Remain Unmerged?" arXiv 2602.00164
- AIDev-pop の fix PR 8,106 件、closed 未マージ 326 件を手作業(約 100 人時)。12 理由。最多はテスト失敗、次が他 PR による先行解決。理由不明の扱い・各割合は abs から未確認。
- 差分: Abujadallah と同系。人間の判断の種類は軸にない。

### Khelifi, Ouni, Khemaja "Behind Agentic Pull Requests: … Developer Interventions in AI Agent-Authored Pull Requests"(MSR 2026 Mining Challenge)
- 人間の介入は APR 52.17% vs 人間 PR 83.59%。介入タクソノミー 4 大分類・42 行為: Guidance 58.02%(エージェントの行動制限・規約の強制)/ Decision 21.16% / 直接コード変更 17.05% / Operational 3.69%。arXiv ID 未確認。
- 差分: 「人間が何をしたか」の行為分類。本研究の H2/H4 と Decision レベルが重なる可能性大。**最も近い競合の一つ。本文未確認なので要精読**。

### Haider & Zimmermann(2026)agent PR のインラインコメント 19,450 件 / 3,177 PR、12 テーマ
- 他論文の引用経由でのみ確認(最多は機能的正しさ、次いでリファクタ・ドキュメント・スタイル)。書誌・arXiv ID 未確認。
- 差分: コメント単位のテーマ分類。「コードから分かるか」の軸はない。

### Takerngsaksiri, Duong, Barnett "Who Finishes the Job? … Follow-Up Fixes and Commit Authorship on AI Coding Agent Pull Requests" arXiv 2609.26847
- AIDev-pop。マージ済み agent PR 4,505 件 vs 同じ repo の人間 PR 5,044 件(abs では 6,774 件と記載、本文の比較対象は 4,505。食い違いは未解決)。30 日以内・同 repo・fix 型・ファイル共有で候補抽出、Claude Opus を判定者(人間 50 ペアで κ=0.77、LLM κ=0.78)。repo 層別の Mantel-Haenszel。
- 結果: 修正が必要になるオッズ 1.41 倍(候補)/ 1.62 倍(検証済み)。検証済み修正の 69.6% は同じエージェント(人間 PR 側は 89.1% が人間)。
- 差分: マージ後の結果。**repo 層別で人間 PR と比べる手法と、LLM 判定者を人間で校正する手順は本研究に必要な水準の参考**。

### Farrag "Reviewing Beyond the Change: Repository Size and Existing Code Across Agent and Human Pull Requests" arXiv 2610.15567
- agent PR 92,042 コメント / 2,034 repo、人間 PR は 1,845 repo。変更外の既存コードに言及するコメントは 6.5%(5.6–7.5)。コードファイル数 10 倍ごとに OR 1.35(1.15–1.59)。agent/人間の勾配比 1.15(1.04–1.27)は事前に決めた無視可能域(1.25)の内側。コンテキストファイル有無の比 1.04(0.78–1.39)。計測器の再現率 43.6%。
- 差分: 「レビュアーが変更の外の知識を使うか」をコード内参照で測った唯一の定量研究。**agent と人間で差がほぼない**という結果は、本研究の「Gerrit と GitHub の差は作者(AI)の効果」という読みに対する反証材料になりうる。事前登録した無視可能域を置く設計は真似る価値がある。

### Russo "For Coding Agents, the Repository Matters" arXiv 2606.28235
- AIDev、マルチレベルモデル。agent PR の解決時間の分散の約 2/5 が repo 間。repo 間分散は agent が人間の 1.76 倍(1.41–2.18)、280 repo。拒否率でも同様。
- 差分: **repo の効果が大きい → 本研究の 100 件(1 repo 2 件まで)の比較は repo 構成の違いで容易に動く**。

### Yu et al. "Beyond Simpson's Paradox: A Cascade of Confounders in AI Agent Pull-Request Co-Authorship" arXiv 2606.22711(KDD 2026 WS)
- AIDev 33,596 PR。共著の効果(マージ率 53.8% vs 79.8%)はエージェント・repo・PR 構造で層別すると消える(Copilot +41.2pt → +4.8pt、Devin +33.5pt → +1.6pt)。
- 差分: 本研究の Gerrit/GitHub・人間/AI 比較が同じ罠にはまる可能性を示す直接の前例。

### Rahman, Alam, Roy, Roy "Who Pays the Review Cost? Triage, Fairness, and Accountability in AI-authored Pull Requests" arXiv 2610.11179
- 実務者 239 人(31 か国)への質問紙。AI PR の受け入れ条件: 範囲が限定的、プロジェクトに根ざした根拠、CI を超えた検証、応答性、マージ後の所有者が明確。「reviewability debt」。「人間の判断を、レビュー資源を消費する前に観測可能にする」ことを提案。
- 差分: 意識調査。主張(人間の判断をレビュー前に可視化せよ)は HUMANS.md の動機とほぼ同じ → **先行として必ず引用し、本研究は行動データ側の裏づけと位置づける**。

## B. 判断がレビュー以外(計画・依頼・承認)に現れる研究

### Park et al. "The Work Behind Delegation: A Framework for Supervising AI Coding Agents" arXiv 2609.24234(cs.HC)
- 経験ある開発者 19 人の観察とワークフロー図、Reddit 議論に適用。Sheridan の監督制御を 7 段階＋ループに再構成。努力は計画に集中、監督作業を他のエージェントに委譲、繰り返す指示を再利用可能な資産に変換。
- 差分: 「判断は計画段階に移る」「指示は資産化される(=AGENTS.md/HUMANS.md)」という定性的根拠。delegation 仮説の先行。リポジトリデータでの定量はない。

### Dhanorkar, Passi, Vorvoreanu "Human oversight of agentic systems in practice" arXiv 2606.05391
- 開発者 17 人のインタビュー。監督は 4 形態: 事前制御 / 共同計画 / 実時間監視 / 事後レビュー。「監督は事後的なだけでなく予防的」。テスト結果を正しさの保証として使うヒューリスティック。
- 差分: 同上。レビューは監督の 4 形態の 1 つにすぎない → **レビューだけ見る本研究は人間の判断の一部しか測っていない**、と査読で言われる根拠になる。

### Monperrus "The End of Code Review: Coding Agents Supersede Human Inspection" arXiv 2606.13175
- ポジションペーパー。エージェントは欠陥検出・スタイル・知識共有・チームの把握というレビューの全目的を人間より安く満たすと主張。abs に実証データなし、人間に残る役割の記述なし。
- 差分: 「スケールに殺される」側の主張そのもの。本研究はこれへの実証的反論(=レビューの目的に入っていない責任・権限の判断は残る)として位置づけられる。

### Pansuriya et al. "Predicting Acceptance and Review Effort in Human and Agent Pull Requests" arXiv 2607.12057
- AIDev の人間・agent PR、提出時情報のみで受け入れを予測(F1>0.95)。テキストの明快さとメタデータが効く。
- 差分: 依頼文・PR 文の質と結末の関連の間接的証拠。Issue の仕様品質そのものは測っていない。**依頼文・Issue の仕様品質とエージェント PR の成否を直接測った研究は今回の検索では見つからなかった**(Abujadallah の提言止まり)。delegation 担当の新規性の余地。

## C. AGENTS.md / HUMANS.md

### Chatlatanagulchai et al. "Agent READMEs: An Empirical Study of Context Files for Agentic Coding" arXiv 2511.12884(2025-11、2026-08 改訂)
- 1,925 repo の 2,303 ファイル。16 種の指示の内容分析: テスト手順 75.9%、実装詳細 70.8%、アーキテクチャ 68.1%、セキュリティ 14.8%、性能 14.5%。設定コードのように小さな追加で進化する。
- 差分: AGENTS.md は「コードから分かること」の指示に偏り、本研究の H 系(方針・責任・権限)はほぼ書かれていない可能性 → HUMANS.md の必要性の傍証。H 系がそこに書かれていたかを照合するのは安価で強い分析。

### "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" arXiv 2602.11988 / "On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents" arXiv 2601.20404 / "Do Context Files Help Coding Agents?" arXiv 2607.27250
- 前者: コンテキストファイルはタスク成功率を概して上げず推論コストを 20% 超増やす(検索結果の要約より。本文未確認)。2601.20404: 実行時間中央値 28.64% 減、出力トークン 16.58% 減(検索結果の要約より。本文未確認)。2607.27250: 未確認。
- 差分: 「文書に書けば効くか」は既に疑わしい。HUMANS.md を「エージェントへの指示」として売ると同じ批判を受ける → **HUMANS.md は人間の責任分担の文書(エージェントの性能を上げるためではない)として定義すべき**。

### 名前の衝突: HUMANS.md は既に複数の別の意味で使われている
- cmdai-hq/HUMANS.md(「エージェントにあなたとの働き方を伝えるオープンフォーマット」= 個人プロファイル)、alsi-lawr/HUMANS.md(エージェントへの行動指示)、LukaGiorgadze/humans.md、thellmwhisperer/human.md、および humanstxt 系の humans.md(作者クレジット)。
- ローカル: outputs/github/humans_exact.json 186 件のうち AI 関連語を含む(ai_hits>0)のは 73 件。
- 差分: 本研究の定義(人間が理解・判断・検証・責任を持つ事項)は既存のどれとも違う。論文では名前を定義し直すか別名にする必要。

## D. 古典(人間同士のレビュー)

### Wang, Xia, Lo, Li "Why is my code change abandoned?" IST 110 (2019) 108–120. doi:10.1016/j.infsof.2019.02.007
- Eclipse / LibreOffice / OpenStack / Qt の Gerrit。各 1000 件を無作為抽出し、**コメントから理由が特定しにくいものを除外**して 1,459 件(Eclipse 309、LibreOffice 590、OpenStack 346、Qt 214)。card sort、Fleiss κ=0.68。
- 12 カテゴリ: Duplicate 40.78%(Already Done 21.73% / Suboptimal Solution 12.40% / Integrated 6.65%)、Lack of Feedback 14.60%、Contributor Operation 10.01%、New Work 8.43%、Incomplete/Wrong Fix 7.54%、Superfluous 4.46%、Test 4.39%、Branch Transfer 2.95%、Merge Conflict 2.74%、Give Up 1.99%、Complicated Change 1.90%、Other 0.21%。98.39% が 1 年以内に放棄。
- 除外率は本文に明記なし。数字から計算すると 4,000 件中 1,459 件が残存(約 36%)→ 人間同士でも約 6 割は理由が読み取れなかったことになる(計算値、著者の記述ではない)。
- 差分: 単位は放棄された変更、本研究は -1/-2 投票。最大カテゴリ Duplicate は本コードブックでは H1 に入る。「重複は人間の文脈か、ツールで検出できる情報か」の境界問題を突きつける。

### Hirao, McIntosh, Ihara, Matsumoto "Code Reviews With Divergent Review Scores: An Empirical Study of the OpenStack and Qt Communities" IEEE TSE (2020)
- 正負のスコアが混在するパッチは複数スコアを受けたパッチの 15%–37%。マージされる方が多い(同強度の正負で平均 71% が統合)。70% で負が正の後に来る。29% が最終的に放棄。
  質的分析: 強い divergence の全 305 件、弱い divergence 630 件、非 divergence 305 件。強い divergence で放棄されるものは外部要因(リリース計画、同じ問題の並行開発)が多い。統合されるものは懸念を間接的に(パッチを変えずに統合タイミング等で)解決。
- 差分: -2 が H 系に偏る(本研究 14/15)ことの先行知見。かつ著者らは「リリース計画や重複検出はツールで自動化できる」と結論 → H1/H4 の一部は「人間にしかできない」ではなく「ツールがまだない」だけ、という反論の根拠になる。

### Mäntylä & Lassenius "What Types of Defects Are Really Discovered in Code Reviews?" IEEE TSE 35(3):430–448, 2009
- 産業 9 件(C/C++)と学生 23 件(Java)のレビュー、欠陥 388 件と 371 件。約 75% が可視の機能に影響しない evolvability 欠陥。機能/evolvability の 2 分類を提示。
- 差分: レビューの主産物は保守性(本研究の C2/C3)。人間の文脈・方針は分類軸にない。

### Beller, Bacchelli, Zaidman, Juergens "Modern Code Reviews in Open-Source Projects: Which Problems Do They Fix?" MSR 2014, pp.202–211
- ConQAT と GROMACS の 1,400 件超の変更を分類。保守性:機能 ≈ 75:25(GROMACS は evolvability 69%)。レビューコメントの 7–35% は捨てられ、変更の 10–22% は明示的なコメントなしに起きる。
- 差分: 同上。「コメントなしの変更 10–22%」は、テキストに出ない判断が人間同士のレビューでもあることの古典的根拠。
